# Correlation and Trace Contract

## Correlation identifiers

Every governed execution has a required `correlation_id` generated by the native OpenProject AgentRun boundary. It is stable across retries and terminal polling. A separate `attempt_id` identifies one execution attempt; a `parent_correlation_id` links child work without replacing the root run.

The canonical envelope carries `tenant_id`, `workspace_id`, `project_id`, `principal_id`, `specialist`, `agent_run_id`, `correlation_id`, `attempt_id`, `trigger`, `observed_at`, and `source_references`. Missing project, principal, specialist, or correlation values fail closed.

## Propagation matrix

| Boundary | Required propagation | Durable record |
|---|---|---|
| OpenProject AgentRun → native job | `agent_run_id`, `correlation_id`, `attempt_id`, project/principal scope | AgentRun, GoodJob execution, audit event |
| Native job → agent runtime | `X-Agent-Key`, correlation headers/body, specialist identity, evidence envelope key | Runtime request/response trace |
| Agent runtime → LangGraph | `thread_id=correlation_id`, attempt metadata, specialist, project scope | LangGraph node trace |
| LangGraph → Langflow | Correlation and simulation/version identifiers | Flow validation/simulation trace |
| LangGraph → Letta | Correlation in state-card update metadata | Letta state operation trace |
| LangGraph → Mem0 | Correlation in scoped memory metadata | Mem0 add/search/delete trace |
| LangGraph → Memgraph | Correlation and source/provenance on query/projection | Graph query/projection audit |
| LangGraph → LiteLLM/model | Correlation in request metadata and provider headers where supported | Model request/response trace |
| Runtime → OpenProject | Correlation, result status, evidence references, approval state | Native AgentRun result and audit |

## Trace records

A trace event contains `trace_id`, `correlation_id`, `attempt_id`, `parent_trace_id`, `component`, `operation`, `specialist`, `project_id`, `status`, `started_at`, `ended_at`, `duration_ms`, `input_reference`, `output_reference`, `provider`, `model`, `tool_name`, `memory_scope`, `evidence_references`, and `error_class`. Payloads store references and redacted metadata, not credentials or unrestricted source content.

## Status and retry rules

Trace status values are `started`, `succeeded`, `failed`, `blocked`, `needs_review`, `cancelled`, and `timed_out`. Retries reuse `correlation_id` and increment `attempt_id`; they must be idempotent at the native AgentRun and evidence envelope boundaries. A terminal failure retains the trace and native error classification.

## Observability requirements

The UI and operator endpoints can join OpenProject AgentRun, GoodJob, runtime, LangGraph, Letta, Mem0, Memgraph, Langflow, and provider records by `correlation_id`. Trace views must show source evidence, memory retrieval/write decisions, tool calls, graph queries, model provider, approvals, and failure state. A missing downstream trace is shown as unavailable; it is never represented as successful execution.
